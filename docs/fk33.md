# SQRL FK33

The FK33 (plain xcvu33p, one SLR, 8 GB HBM2) sets its rails with three digital
potentiometers in its regulators' feedback networks, on an I2C bus wired to
fabric pins. The bridge is `vrmbridge` again, on the FK33's pins and clock, and
`host/fk33set.py` drives the potentiometers. All three rails are settable:
VCCINT, VCCBRAM and VCCHBM.

## No Vivado needed

`SCLINK_FTDI=<serial>` drives the board's FT2232H directly: `host/ftdijtag.py`
reads the IDCODE, loads the bridge with the standard JTAG configuration
sequence (JPROGRAM, CFG_IN, JSTART, DONE) and shifts the bridge register over
MPSSE. It needs `libftdi1` and nothing else (no Vivado, no licence, no
hw_server). The FT2232H must be readable by the user, e.g. a udev rule for
`0403:6010` with the board's serial. The Vivado path works too, without
`SCLINK_FTDI`, given a Vivado that will start.

## What is on the bus

Measured on a board: an address scan with RECEIVE_BYTE (no command byte), then
reads only, then one wiper at a time moved by +4 and +16 codes and put back,
watching SYSMON.

| address | part | role |
|---|---|---|
| `0x2C` | dual 257-step potentiometer, volatile wipers | wiper 0 = **VCCINT** (SYSMON follows it) |
| `0x2E` | same | wiper 0 = **VCCBRAM** (SYSMON follows it) |
| `0x2D` | same | wiper 0 = **VCCHBM** (by elimination: moving it moves no rail the die can see) |
| `0x18`, `0x19`, `0x1F` | Microchip temperature sensors (manufacturer 0x0054, device 0x0201) | board temperatures, read only |

Pins: SCL BB24, SDA BA24 (LVCMOS18). Clock: 200 MHz LVDS on BC26/BC27.

The wipers come up at mid-scale (code 128) on every power-on; nothing here
writes non-volatile memory. Wiper 1 of each potentiometer moves nothing.

## The curve, and modded boards

A **higher code is a lower voltage**, and each rail follows

    V(code) = A + B / (C + code)        mV, code 0..256

| rail | state | A | B | C | code 256 (min) | code 128 (power-on) | code 0 |
|---|---|---|---|---|---|---|---|
| VCCINT | stock | 733.04 | 13625.3 | 51.587 | 777 | 809 | 997 |
| VCCINT | modded | 600.01 | 13622.2 | 51.573 | 644 | 676 | 864 |
| VCCBRAM | stock | 772.50 | 17662.6 | 102.774 | 822 | 849 | 944 |
| VCCBRAM | modded | 600.01 | 35325.8 | 102.779 | 698 | 753 | 944 |
| VCCHBM | stock | 1051.49 | 46239.1 | 154.506 | 1164 | 1215 | 1351 |
| VCCHBM | swapped | 900.00 | 46234.2 | 102.787 | 1029 | 1100 | 1350 |

The constants are fitted to the FK33 conversion chart TeamRedMiner published
with its resistor-mod guide (`doc/FPGA_FK33_MOD.txt` in their repository); the
fit reproduces all 257 rows of every table to within its 0.1 mV rounding. The
mod it describes removes R30 (VCCINT), removes R61 and R62 (VCCBRAM), and
optionally swaps R84 and R57 (VCCHBM). A is the asymptote that guide quotes as
the third figure of each range ("997-777 mV, 733 mV"); no code reaches it.

On a real stock board SYSMON read the curve plus a few millivolts (VCCINT +3,
VCCBRAM +2 at code 128) and followed every step of a ladder to within 1 mV.
The tool calibrates that offset at the start of each run.

**The mod state is measured, not assumed.** At the wiper's current code the
tool compares SYSMON with both curves:

- VCCINT: the curves are 133 mV apart at every code, so one reading decides.
- VCCBRAM: the curves meet near code 0 (0.7 mV apart) and are 66 mV or more
  apart from code 48 up. Below code 48 the tool steps the wiper to 128 first,
  which lowers the rail on either curve, and then decides.
- VCCHBM: no on-die witness, so no detection. It is taken as stock unless
  `--hbm-mod swapped`. At every code the swapped curve is at or below the stock
  one, so the default can only err toward undervolting.

`--fk33-mod stock|modded`, if given, has to agree with the measurement or
nothing is written.

## How the tool protects the part

All in `host/fk33set.py`:

1. **Ceilings** are DS923's recommended maxima: VCCINT and VCCBRAM 876 mV,
   VCC_HBM 1236 mV. Not overridable. Code 0 on a stock board would be 997 mV
   VCCINT and is refused.
2. **Small steps**: the wiper moves so that each step changes the modelled
   rail by at most 10 mV. Every step is written, read back from the
   potentiometer and, on VCCINT and VCCBRAM, checked against SYSMON (8 mV). A
   step SYSMON does not follow puts the rail back where it started.
3. **The HBM wiper is watched from outside**: each VCCHBM step must leave
   VCCINT, VCCBRAM and VCCAUX within 6 mV, or the move is undone.
4. Only volatile wipers are written. TCON, non-volatile memory and the
   sensors are never written. A power cycle returns all three rails to code
   128.
5. `min` is code 256, `default` is code 128 (the power-on state), anything else
   is millivolts within what the board's curve reaches.
6. **Floors** (added 2026-10-26): a target under the lower of DS923's
   recommended minimum (VCCINT and VCCBRAM 825 mV, VCC_HBM 1164 mV) and the
   board's own power-on level is refused unless `--below-spec` is given. The
   power-on term exists because the FK33 ships under DS923 on VCCINT (stock
   809 mV, modded 676 mV), and `default` must always be reachable. In practice:
   `min` on VCCINT needs `--below-spec` on every board, and so does `min` on
   VCCBRAM on a modded board; stock VCCBRAM `min` (~825 mV) is at the minimum
   and passes. Undervolting lowers current, so it is not a known way to damage
   the card, but below the floor the fabric has no timing margin and the
   regulators sit at the bottom of their feedback range with no telemetry on
   this board to show how they cope. Boards are run there routinely (third-party
   FK33 tooling suggests 777 mV); the point is that it is asked for, not reached
   by default.
7. **Temperatures** (added 2026-10-26): nothing is written while the die
   (SYSMON) or any of the three board sensors (0x18, 0x19, 0x1F) reads 85 °C
   or more, or while the board sensors do not answer at all. Every ramp step
   re-reads them, and a step that finds the card too hot puts the rail back
   where it started. `--show` still works on a hot card. The sensors are
   printed again after the change.

Why 6 and 7 exist: on 2026-10-26 a stock FK33 at VCCINT 780 mV, VCCBRAM and
VCCHBM at `min`, died about 25 s into a heavy user design (375 MHz, die
47.5 °C). The USB-JTAG chip dropped off and the board no longer brings up most
of its rails, on any host. Neither the settings nor the load were unusual
for an FK33 and the cause is not known (an aged regulator or fuse is the
leading guess). The I2C sensors above are reachable only through vrmbridge,
so this tool is the one moment their readings can gate anything. The board's
power lines are another matter: any design can read them, see
[Board power telemetry](#board-power-telemetry-sysmon-auxiliary-inputs).

The setting is global and survives reconfiguration, so the design loaded next
inherits it. `min` on VCCHBM breaks any design that uses the HBM.

## Board power telemetry (SYSMON auxiliary inputs)

The I2C bus above carries no current monitor. The FK33's power telemetry is
**analog, wired to SYSMON's auxiliary inputs in bank 66** (SQRL's own
`fk33_jtagaxi.tcl` reads it this way). Any design that connects those pins can
read the 12 V input and the current-sense lines of the three main rails,
including over JTAG while that design is running.

| SYSMON channel | pins (P / N) | status register | signal | conversion |
|---|---|---|---|---|
| VAUX0  | AV33 / AW33 | `0x10` | 12 V input | `code / 65536 * 15.2` V |
| VAUX5  | BC35 / BD35 | `0x15` | VCCINT current sense | `code / 65536` V (sense; scale below) |
| VAUX12 | BB36 / BC36 | `0x1C` | VCCHBM current sense | `code / 65536` V |
| VAUX13 | BE34 / BE35 | `0x1D` | VCCBRAM current sense | `code / 65536` V |
| VAUX4  | BB34 / BB35 | `0x14` | LTC3636 (VCCAUX) temperature | `code * 400 / 65536 - 273.15` °C (SQRL's formula) |
| VAUX8  | AY34 / BA34 | `0x18` | LTC3636 (VCCMGT) temperature | same |

Pins are the package's `IO_*_AD<n>P/N_66` on xcvu33p-fsvh2104 (Vivado 2024.2).
All channels are unipolar with a 1 V full scale.

**The current-sense scale is not published.** SQRL's script reads the three
sense registers but never converts them to amps, and no schematic exists. To
turn sense volts into amps, calibrate your own board: hold the rail voltage
fixed, record the sense voltage and the board's input power (a wall or 12 V
clamp meter) at two or more loads, and fit amps per sense-mV from the
difference. Until you have that, report sense volts, not invented amps. The
12 V reading needs no calibration.

Measured with `vrmbridge` on a stock board, idle (no user design, 2026-11-07):
12 V in 12.14 V; sense VCCINT ~26.5 mV, VCCHBM ~36.7 mV, VCCBRAM ~45.4 mV;
LTC3636 ~25 / ~31 °C. Three reads in a row agreed within ~1 mV.

### Reading it from your own design

Instantiate SYSMONE4 with the six channel pairs connected and the sequencer
converting them. These are the System Management Wizard's values for this
channel set (2024.2); `INIT_41` here keeps over-temperature shutdown enabled:

```systemverilog
// pins: see the table; nothing in the fabric drives them
wire [15:0] vauxp = {2'b00, vaux13_p, vaux12_p, 3'b000, vaux8_p, 2'b00, vaux5_p, vaux4_p, 3'b000, vaux0_p};
wire [15:0] vauxn = {2'b00, vaux13_n, vaux12_n, 3'b000, vaux8_n, 2'b00, vaux5_n, vaux4_n, 3'b000, vaux0_n};
SYSMONE4 #(
    .INIT_41(16'h2F9E),   // continuous sequence, calibration on, alarms off except over-temperature
    .INIT_42(16'h2800),   // ADC clock = DCLK / 0x28: 5 MHz from 200 MHz; keep it <= 5.2 MHz
    .INIT_48(16'h4F01),   // calibration, temperature, VCCINT, VCCAUX, VCCBRAM
    .INIT_49(16'h3131)    // VAUX 0, 4, 5, 8, 12, 13
) u_sysmon (.VAUXP(vauxp), .VAUXN(vauxn), .DCLK(clk), /* DRP, or tie off and read over JTAG */ ...);
```

```tcl
set_property PACKAGE_PIN AV33 [get_ports vaux0_p];  set_property PACKAGE_PIN AW33 [get_ports vaux0_n]
set_property PACKAGE_PIN BB34 [get_ports vaux4_p];  set_property PACKAGE_PIN BB35 [get_ports vaux4_n]
set_property PACKAGE_PIN BC35 [get_ports vaux5_p];  set_property PACKAGE_PIN BD35 [get_ports vaux5_n]
set_property PACKAGE_PIN AY34 [get_ports vaux8_p];  set_property PACKAGE_PIN BA34 [get_ports vaux8_n]
set_property PACKAGE_PIN BB36 [get_ports vaux12_p]; set_property PACKAGE_PIN BC36 [get_ports vaux12_n]
set_property PACKAGE_PIN BE34 [get_ports vaux13_p]; set_property PACKAGE_PIN BE35 [get_ports vaux13_n]
set_property IOSTANDARD ANALOG [get_ports {vaux*_p vaux*_n}]
```

`IOSTANDARD ANALOG` is required: with LVCMOS18 Vivado raises critical DRCs
(ANALOGSTD-2, IOSTDTYPE-1) on every pin. Without the SYSMONE4 connection the
pads are not analog inputs at all, and registers `0x10`+ read 0 no matter
what the sequencer is told over JTAG. So a design has to opt in at build time.

**From the host, while the design runs:** the TAP's `SYSMON_DRP` instruction
(IR `0x37` on xcvu33p, IR length 6) reaches the same registers without
touching the design's logic. Shift a 32-bit DR word `(1 << 26) | (addr << 16)`
(a DRP read), then shift again; the low 16 bits of the second shift are the
register. On this one-SLR die the shift is exactly 32 bits: a 33rd bit, right
for two-SLR parts, misaligns the command and every read returns 0.

### In this tool

`vrmbridge_fk33` is built with the six inputs (`FK33_AUX`). Two read-only
bridge commands return the cached codes:

| op | result |
|---|---|
| `0x09` AUX  | `{VAUX13, VAUX12, VAUX5, VAUX0}`, 16 bits each |
| `0x0A` AUXT | `{0x5641 ("VA"), 0, VAUX8, VAUX4}` |

The `0x5641` tag tells a bridge with the inputs from an older one.
`fk33set.py --show` (and the end of every rail change) prints them:

```console
board analog: 12 V in 12.14 V; current sense (uncalibrated) VCCINT 26.5 mV, VCCHBM 37.0 mV,
VCCBRAM 46.0 mV; LTC3636 VCCAUX 24.6 C, VCCMGT 30.8 C; raw {...}
```

## A note on SYSMON clocking

`vrmbridge` divides its clock for SYSMON's ADC. Divide-by-4 suits the TH53/TH55's
100 MHz; at the FK33's 200 MHz it ran the ADC at 50 MHz, far above its limit,
and every reading came back 0. The divider now scales with `CLK_HZ` for clocks
above 100 MHz (40 at 200 MHz, a 5 MHz ADC clock); the TH builds are unchanged.

## Status

- **Confirmed on hardware** on a stock FK33: detection, all three rails to
  `min` and back to `default`, through `changeVoltage.sh` with `SCLINK_FTDI`.
- **Not yet run on a modded FK33.** The modded curves are the fitted chart;
  the detection is built to refuse rather than guess when a board fits neither.
- **Board power telemetry** (12 V in, rail current sense, regulator
  temperatures) read on a stock board through the bridge (`--show`, read only).
  The rail-setting path in this build is the same PMBus logic as before and
  passed timing; a rail change has not been repeated on hardware with it yet.
  The current-sense scale is uncalibrated (see above).
- `fk33set.py --selftest` covers the models, detection both ways, every
  refusal, and abort-and-restore against a fake board.
